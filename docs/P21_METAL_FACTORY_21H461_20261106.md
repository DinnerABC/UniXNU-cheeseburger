## Actual callback and registration order
There is **no exact `_MTLCreateDevice` local definition or public export** in the selected original Metal image. Do not invent its implementation. The actual factory analyzed is `_MTLCreateSystemDefaultDevice`, `_MTLRegisterDevices`, and `_MTLAddDevice`.

1. `_MTLRegisterDevices` obtains IOMasterPort, enumerates IOAcceleratorES services, and calls `_getMetalPluginClassForService`.
2. On a principal class it performs objc allocation, `initWithAcceleratorPort:` with x2=the service handle. Nil skips registration. Non-nil is saved in x20 and passed to `_MTLAddDevice`.
3. `_MTLAddDevice` requires `_deviceArray != NULL`, then real conformsToProtocol checks for MTLDevice and MTLDeviceSPI. Missing either invokes `_MTLReleaseAssertionFailure` and BRK; returning an NSObject-only controlled device is not valid.
4. Synchronous order: **initLimits → initFeatureQueries → initWorkarounds**. `initFeatureQueries` itself calls **initGPUFamilySupport**, alloc/initWithDevice: MTLDeviceFeatureQueries into self+0x160, then tail-calls **validate**. Do not call initGPUFamilySupport a second time unless the implementation requires it.
5. Conditional platform path calls allowLibrariesFromOtherPlatforms. Registration then dispatch_syncs `_deviceArrayQueue` to `___MTLAddDevice_block_invoke`.
6. With a wrapper hook, `_deviceWrapper` may replace the object, or a hook constructs a wrapper when the same object is returned. Finally `[_deviceArray addObject:object]`. The hook-produced wrapper path performs a balancing release after addObject; ordinary path does not add a spurious release.
7. After `_MTLAddDevice` returns, `_MTLRegisterDevices` releases its allocated device held in **x20**, then IOObjectRelease(service), finally IOObjectRelease(iterator). Service is borrowed during initializer; asynchronous use requires its own retain. Base class has no stored accelerator-port ivar and no base port release.

The non-wrapper normal lifecycle is alloc/init (+1) → array retains → factory balances +1; it is not alloc/init→autorelease→extra release. Hook semantics need a runtime test only if that hook is enabled. Default-device return ownership must follow the original factory's block/retain implementation, not the absence of a retain in its outer wrapper.

## Base class initializer/destructor
* `_MTLDevice` superclass NSObject, instance size536 (0x218), `_limits` self+8, size264 (0x108).
* `initWithAcceleratorPort:` is **abstract/unimplemented**, calls `objc_msgSend$doesNotRecognizeSelector:` with original _cmd in x2 and returns nil. It does NOT delegate to init or set the port. A subclass must use `[super init]`, own its real driver session, and on failure balance the allocated object; do not call this superclass accelerator initializer.
* `init` invokes NSObject super init; on success creates serial, pipeline-serialization, and concurrent dispatch queues at self+0x118/0x120/0x128; constructs MTLLibraryBuilder (self+0x178), pipeline-library builder (self+0x180) and its queue; calls initSerializationPaths; allocates progress tracking array, loader/resource-list pool, initializes environment-derived flags, archive pointers, and workaround bits. It does **not** run initLimits or feature-family callbacks. Skipping super init leaves base destructor/framework state uninitialized.
* `dealloc` destroys both builder allocations, releases their queue plus all three base dispatch queues, releases featureQueries, frees supportedGPUFamilies vector allocation/self+0x110, releases progress/pipeline/loader/pool/plugin/architecture objects and destroys archive DBs, then calls NSObject super dealloc. Subclass must release only its own real resources exactly once before super dealloc; no memset/free of Apple's embedded ivars and no fake ownership.

Exact init/dealloc/accelerator annotated calls are retained in private files. Runtime export resolutions in these files are authoritative; unresolved private optimized calls are explicitly address-labelled.

## Minimum still needed for a truthful system factory
1. A real `_MTLDevice` subclass with superclass init, correct owned session/resources, MTLDevice+MTLDeviceSPI ABI signatures and method behavior. No registration of the existing controlled NSObject device.
2. Actual supported limits/profile queries; make initLimits/featureQueries/GPU-family callbacks coherent with the finite native renderer rather than inheriting a different GPU's capability advertisement. The recovered full layout now permits version-correct field projection, not capability fabrication.
3. FeatureQueries initWithDevice:/validate, device-wrapper and default selection behavior require only the precise selectors they actually call, with verified encodings; any missing selector is a concrete TODO, not a claim that factory support is complete. Their bounded call evidence, if symbol-defined, is saved in feature-query-calls.json. No system-factory live probe was performed here.
4. Native triangle requires real render pipeline/attachments/texture resources/draw submission/fence/readback/presentation, not just factory conformance. The earlier padding_gradient compute object chain proves a fixed genuine metallib route, not system rendering.
5. Retain/release counters and borrowed service lifetime can be validated in a separate authorized runtime probe after code pin is checked. On failure return nil with resources balanced; do not fake success or claim family support to make registration pass.
