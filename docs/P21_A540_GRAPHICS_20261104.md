## Ported path

`package/BoardRuntime/CheeseburgerGpuBlit540.h` emits, into an ordinary
indirect buffer of the existing `Engine540`:

1. `restore()`: the A5xx linear/GMEM-bypass baseline (SP/RB/TPL1 64-bit
   addressing, UCHE invalidate, HLSQ update, PC/GRAS/RB/VPC/SP/TPL1 defaults,
   `RB_CCU_CNTL=0x10000000`, `RB_CNTL=BYPASS`), register for register from
   sagit `AdrenoPipeline.h:345-400`.
2. `begin2D()`: Mesa fd5 sysmem events 25 (CCU invalidate) and 24 (UCHE flush).
3. `solidFill()`: `CP_SET_MODE`/BLIT2D (`0x6c`=5), `RB_2D_*` destination
   registers with format 75 (RB5_R32_UINT), the solid source dwords, the
   `CP_BLIT` packet (`0x2c`) with pixel bounds, END2D (`0x6c`=8), then a color
   cache flush: `CACHE_FLUSH_TS` event 29 and `CP_WAIT_REG_MEM` on the sequence
   word. This is RB/GRAS/CCU work, not `CP_MEM_WRITE`.
4. The normal Engine540 completion timestamp fences the whole stream.

`package/BoardRuntime/A5xxRegs.h` is generated from Mesa
`src/freedreno/registers/adreno/a5xx.xml` with `gen_header.py` (the same
generator sagit uses). The local Mesa is 26.2; Mesa 26 merged
`RB_2D_SRC/DST_LO/HI` and `UCHE_CACHE_INVALIDATE_MIN/MAX` into `reg64`
entries, so the header keeps the older symbol names as aliases at the same
offsets. Nothing in the encoding depends on a newer field definition.

## Boot-time test (`cheeseburger-gpu-clear`, default on)

After the second ring keep-alive the probe:

1. allocates an 8 KiB IB page, a 64 KiB linear 256x64 RGBA8 target and a 4 KiB
   flush/wait page (all kernel-owned), zeroes them, and maps them at
   `0x2040000`, `0x2060000` and `0x2050000` **outside** `gSubmitLock`;
2. encodes one `restore()` and four 128x32 solid fills, one per quadrant, each
   with its own END2D and color flush;
3. submits through the verified `cheeseburger_gpu_engine_submit` path (pre-kick
   power check, TLBIALL, ATOS/kit leaf gate, fence) and reads the centre of
   each quadrant plus an edge sample with the CPU;
4. repeats the same engine for a 96-row band at the top of
   `PE_current_console()`, which is GPU-authored pixels on the panel without a
   CPU copy.

Results are logged as `CB GPU clear:` and persisted as the `CLR` line
(`rc/seq/words`, four pixels, edge, match, `ib/tgt` physical addresses, scanout
result). A failure keeps every page and mapping for the boot.

## Display handoff constraints (P21-Curlew/Dunlin)

Two measured constraints block a direct GPU scanout on this board:

| Constraint | Evidence | Consequence |
|---|---|---|
| Firmware GOP pitch is 4320 bytes (1080x1920, depth 32) | `prep=-5 pe=1080/1920/4320/32` (boot `0x40a26751`) | `RB_2D_*_SIZE.PITCH` counts 64-byte units; 4320 is not encodable, so the 2D engine cannot write the GOP buffer. |
| MDP5 `PIPE_SRC0_ADDR` is 32-bit in this path | A 1088x1920 frame allocated at `pa=0x111876000` (4.58 GiB) was rejected by the flip hook (boot `0x40a433bd`) | A GPU-filled full frame cannot be scanned by MDP until it is allocated below 4 GiB or the path is extended to the IOMMU. |

The kernel now records both facts and leaves the display untouched on failure.
The next path is sagit's compute fallback: an IR3 compute shader using
byte-addressed global stores can write the GOP buffer at its real pitch
(4320) without the 64-byte destination rule, which also avoids the 4 GiB MDP
limit because the writes go through the GPU SMMU address space.

## Compute shader attempt (P21-Egret/Gannet)

Mesa 26.2's IR3 assembler produces a5xx machine code for a 32-word compute
shader (`shl.b` + `stib`), and `CheeseburgerGpuCompute540.h` emits sagit's
compute dispatch (CS config, shader object, SSBO descriptors, NDRANGE, CP
`0x33`, `flush(4)`). On hardware the stream fences (`rc=0`, seq 9..12,
words=360), but a probe that writes `0xdeadbeef` into a private 4 KiB SSBO
reads back zero, and the scanout band still holds `ff000000`. The GPU reports
bit 30 busy after the dispatch while the later user submission still works, so
the CP accepted the dispatch but the shader did not produce observed writes.
The next step is a completion delay plus a state-variant matrix (WGID/UNK 0,
thread size, control bits, single-thread dispatch) in one boot.

## Why this shape

- sagit and the OnePlus 5 are both MSM8998/A540, so the 2D state and the CP
  packets are the same hardware contract. The board-dependent parts (power,
  clocks, SMMU, firmware, ring) remain this port's own, already verified code.
- The ABI has no per-job resource list, so the service holds every mapped BO
  of the client until the job's fence. That is the safe superset for IB data,
  textures and write targets.
- A5xx has no Turnip backend. This 2D engine is the first real graphics path
  available without a shader compiler; the next step is the VSC/RB triangle
  path using sagit's `PipelineEncoder` and IR3-generated shaders.
