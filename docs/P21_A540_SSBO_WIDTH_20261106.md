# A540 SSBO WIDTH 修复与真实 shader 写入验证 · 2026-11-06

## 明确源码差异

固定 sagit `673f85070fe9f7872793015eb230a5c3987d4a8c` 的
`drivers/gpu/QcomGPU/AdrenoPipeline.h::buffers` 与固定 Mesa24.3.4
`769e51468b49b2a42f0a0eaf71cf9eed5ff4e5de` 的
`src/gallium/drivers/freedreno/a5xx/fd5_emit.c::emit_ssbos` 都使用：

```cpp
A5XX_SSBO_1_0_WIDTH(bytes & 0xffff)
A5XX_SSBO_1_1_HEIGHT(bytes >> 16)
```

A540 SSBO 第一尺寸 word 的 WIDTH 在 bits31:16，FMT在bits15:8；第二 word 的
HEIGHT在bits15:0。本机原移植直接写 `bytes & 0xffff`，漏掉WIDTH的位域编码。
256字节由此变成 `word0=0x00000100`（WIDTH0/FMT1），正确值应为
`word0=0x01000000`（WIDTH256/FMT0）。常量c24.x长度正确并不能弥补硬件descriptor错误。

## 已应用修复

- `package/Userland/NativeMetal540Compute.h`：两尺寸word使用正式WIDTH/HEIGHT宏。
- `package/BoardRuntime/CheeseburgerGpuCompute540.h`：同类遗漏同步修复；活动候选仍不执行旧A6xx ISA。
- `tests/native540_probe_model.cpp`：从实际编码包解出WIDTH/HEIGHT，明确验证256字节，FMT未被误写。
- `tests/native540_compute_model.cpp`：包值及64KiB边界特例使用正确位域，并新增静态断言。

没有改shaderISA、常量、工作组、BO地址、认证、SMMU、安全门禁或完成路径。
4项probe tests、7项dynamic compute tests、ASan/UBSan、arm64编译及包边界模型PASS。
之前的host模型只比较错误原始word，不解码WIDTH；这个盲点现已纠正。
