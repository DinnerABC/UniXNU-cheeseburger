# A540 shader path and core-domain transition (2026-11-05)

This round implements the missing prerequisite for any A540 shader work — the
RBCCU/SP core power domains — and finishes the sagit-style compute dispatch so
a shader can be uploaded, launched and read back. It is the first round after
the 2D-only baseline that emits a shader stream.

## Why the SP domain is the gate

A CS or VS/FS only runs on the shader processors. P21-Lapwing measured that
after our runtime PAS authenticate both core domains read back down
(`rbccu=778801/1 sp=778001/1`), while the 2D engine (RB/RAC) keeps working —
which is exactly why every 2D test passed and every compute dispatch fenced
without writing.

The reason is the difference in ZAP handling, not a hardware quirk:

- sagit's loader authenticates the ZAP image; the kext only calls the PAS
  **resume** action, so the subsystem is never reset under the running driver.
- Our board performs the full runtime PAS chain (`init` → `mem_setup` →
  `authenticate`) because the firmware does not pre-authenticate the image.
  That authenticate step resets the GPU core domains.

Android does the same authenticate and then calls `a5xx_pm_resume` to turn the
domains back on. The vendor rule is that the power-up command may only be
written with the CP stopped (P21-Quail: writing it to a live CP stopped the
engine within a millisecond).

## Implementation

### 1. Core-domain transition (`resumeCoreDomains`)

`CheeseburgerGpuCp.cpp` adds a transition that reuses the halt/drain/resume
already proven by every SMMU table update (`CheeseburgerGpuQuiesce.h`):

1. Preconditions: engine ready, not failed, not SMMU-faulted; read the two
   status registers (bit 20 = domain up). If both are already up, do nothing.
2. `drainForTables()`: halt CP and VBIF, require the empty ring, the idle
   status and `Status3` bit 24 clear.
3. Write `0x778000` to the RBCCU control (`0xa887`) and then the SP control
   (`0xa881`) as **posted** writes with a 3 ms settle (sagit order).
4. `resumeAfterTables()`: resume the same empty ring and verify the cursors.
5. Only after the CP is live, read the two status registers back.
6. The caller runs a ring keep-alive fence; a transition that did not leave a
   working CP fails closed and quarantines the engine.

No GPU/GPMU register is read while the AXI is halted. A failure leaves the
engine halted and refuses every later submission, as every other GPU failure
does on this board.

Boot args:

- `cheeseburger-gpu-compute=1` — run the shader test at all (default 0, so a
  normal boot never enters the transition).
- `cheeseburger-gpu-core-resume=1` — default 1 inside the test; set 0 to keep
  the old "dispatch fences, nothing writes" control.

### 2. Shader upload and dispatch

The existing encoder already matched sagit's order. This round keeps the
standard HLSQ fetch path (`CP_LOAD_STATE4`, block 13) and adds/verifies:

| sagit | Ours |
| --- | --- |
| `restore()` (linear) then `SP_SP_CNTL=0` | `Blit540::restore()` then same |
| `HLSQ_CONTROL_0` CSTHREADSIZE + 0x880 | same |
| CS VS/FS config/constlen/instrlen zeroed | same |
| `SP_CS_CTRL_REG0` 0x2 + BUFFER + thread/reg/branch fields | same |
| `HLSQ_CS_CNTL` instrlen + SSBO_ENABLE | same |
| `SP_CS_OBJ_START` 6-word object | same |
| `HLSQ_UPDATE_CNTL=0x1f00000` | same |
| `HLSQ_CS_CNTL_0/1` | same |
| SS4 code load (`0x30`, block 13) | same |
| SSBO descriptors block 15, 16 entries, sizes then addresses | same |
| NDRANGE 0..6, KERNEL_GROUP 1/1/1 | same |
| CP `0x33` `{0,groups,1,1}` + idle | same |
| `flush(4, cell)` = idle, CACHE_FLUSH_TS, WAIT_REG_MEM, idle | `flushWait(scratch,4)` |

The shader is Mesa IR3 for A540, assembled by the host tool in `tools/gpu-ir3`
(32-word unit, `instrlen=1`, `constlen=0`, `max_reg=1`,
`double_threadsize=1`, `localid=0`, `wgid=252`). Two programs:

- `ScanBand540`: `r1.x = id << 8`, store to SSBO 0 at dword `id`.
- `Probe540`: store `0xdeadbeef` to every covered dword.

### 3. Device test and records

`cheeseburger_gpu_compute_band_test()` now:

1. runs the transition and a keep-alive fence;
2. runs the seven CS state variants (each into its own page of a private 8-page
   buffer);
3. runs the constant probe into page 7;
4. runs the scan band into the firmware scanout rows 0..63 (the real 4320-byte
   pitch, which the 2D engine cannot encode);
5. reads every sample back from CPU-owned memory after a 20 ms settle.

New persistent records: `CORE` (domain status before/after + transition rc +
fence) and `SHDR` (isolated constant probe). `CMPT` (band) and `CPRB`
(variants) are unchanged.

## Service lifecycle fixes

`CheeseburgerGpuService.cpp`:

- `clientMemoryForType` and `BoCpuUnmap` now refuse imported BOs. The ABI says
  an imported BO has no CPU-map token; the caller keeps its own mapping and
  cache mode.
- `BoImport` refuses a client without a task.
- `BoMap` rejects a range overlapping an IOVA retained after a failed unmap, so
  a new BO can never rewrite a leaf translation that could not be torn down.
- `clientClose()`/`free()` serialize the BO table with `run()` under the same
  client lock before freeing or quarantining.

Unchanged and retained: per-job holds of every mapped BO until the fence,
fail-closed holds after a failed kick, quarantine retired only after fence +
idle, and the per-submit TLBIALL.
